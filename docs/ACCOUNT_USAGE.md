# DeepL 계정 사용량 표시

UI에 앱의 요청 예약 수/문자 합계를 계정 사용량처럼 표시하지 않는다. DeepL 선택·데모 해제·전송 동의 및 키 설정 후 실제 번역 시작 시 `/v2/usage`를 조회한다. 정지 상태에서 수동 새로고침도 가능하다. 최초 앱 실행이나 데모/로컬 모드에서는 조회하지 않는다. 조회는 API 키 인증만 보내며 대사/이미지를 포함하지 않는다. 실제 키로 검증한 것은 아니며 모든 자동 테스트는 목업이다.

- Free: `GET https://api-free.deepl.com/v2/usage`
- Pro: `GET https://api.deepl.com/v2/usage`
- 인증은 Go 코어의 Authorization 헤더에서만 사용한다. UI에 키를 다시 표시하거나 응답/오류에 키를 넣지 않는다. 기존 TLS 검증과 리디렉션 차단을 유지한다.
- UI/코어 모두 최소 60초 간격. 실패도 제한에 포함하며 자동 재시도하지 않는다. 사용량 조회로 앱 번역 안전 카운터를 늘리지 않는다.
- `character_count`는 현재 청구 기간의 **계정 전체** 문자 수다. 제품별 내역과 현재 키 사용량은 다를 수 있다. `api_key_character_count/limit`가 있으면 별도 표시한다. 문자 수를 요금으로 환산하지 않는다.
- `character_limit` 및 키 한도 `1000000000000`은 공식 문서상 **한도 미설정**이다. 누락은 'API 미제공'으로 구분하며 0이나 무제한으로 추정하지 않는다.
- 응답 수신 시각을 로컬 시간으로 표시한다. 서버 반영에 몇 분 걸릴 수 있으므로 실제 계정의 순간 사용량이라고 보장하지 않는다. 조회 실패·키/제공자 변경·늦은 응답은 미조회/현재 값 알 수 없음으로 표시한다. 이전 값을 새 값처럼 갱신하지 않는다.
- 앱 내부 100회/10,000자 세션 제한과 호출 간격 제한은 계속 적용한다. 도달 시 '앱 안전 세션 제한'임을 표시하고 정지한다. 계정 한도와 별개며 실패한 예약도 포함할 수 있다. 실제 API 한도 응답은 따로 안내한다.

공식 근거: https://developers.deepl.com/api-reference/usage-and-quota/check-usage-and-limits
Free/Pro Classic 응답과 Pro 제품별/키별 응답 형태가 다름을 확인했다. 이 UI는 계정 문자 총합과 제공된 키별 문자 수에 집중하며 문서/음성 제품별 내역은 표시하지 않는다.
