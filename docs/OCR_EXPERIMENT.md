# Linux 합성 일본어 OCR 실험

2026-11-13, Linux Tesseract 5.5.0, 기존 Go 코어 0.2.0의 JSONL `ocr` 경로를 실제 실행했다. NotoSansCJK-Regular.ttc 40px로 흰 배경 700×100 이미지에 자체 예제 문장을 그려 PNG 메모리 입력으로 전달했다. 화면 캡처·게임·번역 API·Windows 실행은 없었다.

공식 tessdata_fast 고정 커밋: `87416418657359cb625c412a48b6e1d6d41c29bd`. [모델 출처](https://github.com/tesseract-ocr/tessdata_fast/tree/87416418657359cb625c412a48b6e1d6d41c29bd). 다운로드 바이트의 Git blob SHA1을 공식 contents 응답의 blob과 비교했고 일치했다. SHA256은 `1f5de9236d2e85f5fdf4b3c500f2d4926f8d9449f28f5394472d9e8d83b91b4d`. 이는 같은 출처의 콘텐츠 무결성 검사이며 서명 검증이나 파일 안전성 보증은 아니다. Apache-2.0 LICENSE도 함께 읽었다. 모델·폰트는 프로젝트/설치본에 추가하지 않았다.

원시 출력에는 마지막 줄바꿈이 있어 바이트/문자열 완전 일치 검사는 3개 모두 false였다. 앱의 공백 정규화 후 비교하면 3개 모두 일치했다. 위 시간은 공유 Linux 환경에서 각 1회 관찰한 값이며 저사양 목표, p95 지연이나 Windows 성능 근거가 아니다. 장식 글꼴·루비·세로쓰기·게임 배경·애니메이션·화면 좌표 정확성은 시험하지 않았다.
