# 자막 위치와 크기 편집

일반 자막 창에는 제목 표시줄, 최소화·최대화·닫기 버튼이 없습니다. 플레이 모드는 클릭을 게임으로 통과시키며, 학습 모드에서는 일본어 텍스트를 선택합니다. 이동은 별도 **자막 위치 · 크기 편집**에서만 합니다. 텍스트 선택 드래그와 창 이동 드래그를 구분합니다.

편집을 열면 캡처를 중지합니다. 파란 위쪽 막대를 끌어 이동하고 아래 막대를 끌어 크기를 바꿉니다. 숫자로 위치와 크기를 입력할 수도 있습니다. 드래그를 놓으면 연결된 한 모니터 안으로 창을 복구합니다. 저장을 누르면 다음 실행에도 같은 배치를 사용하고, 취소하면 이전 배치로 돌아갑니다. 편집용 막대는 닫을 때 제거됩니다. 편집 완료 후에는 원래 플레이/학습 모드를 복구하지만 게임 창과 영역을 확인하기 전 자동 캡처 재개는 하지 않습니다.

## 저장과 복구

`onboarding.data_folder()` 아래 `overlay-placement.json`에 버전·x·y·width·height만 저장합니다. 설치형은 기존 사용자 데이터 폴더, `portable.flag`가 있는 휴대형은 실행 폴더의 `data`를 사용합니다. API 키·대사·이미지는 저장하지 않습니다. 불투명도 파일 `overlay.json`과 독립적입니다. 같은 폴더의 임시 파일에 기록하고 원자 교체하므로 실패하면 기존 설정을 보존합니다. 잘못되거나 2 KiB를 초과한 파일은 오류로 보고하며 조용히 덮어쓰지 않습니다.

모니터가 분리됐거나 배치가 화면 밖이면 가장 많이 겹치는 실제 모니터(없으면 첫 모니터) 안으로 복구합니다. 가상 데스크톱의 빈 틈은 화면으로 취급하지 않습니다. 왼쪽/위쪽 모니터의 음수 좌표도 유지합니다. 최소 크기는 240×120, 최대 크기는 3840×2160 픽셀입니다. 화면보다 크면 해당 모니터에 맞춰 줄입니다. 모니터 전체 경계를 사용하므로 작업 표시줄 영역까지 사용할 수 있습니다.

## 통합 계약

부모 앱은 Tk 창 생성 **이전**에 모니터별 DPI 인식을 설정해야 합니다. `require_physical_coordinates()`는 Windows 스레드 DPI 인식이 per-monitor인지 확인하고 아니면 이동을 거부합니다. 이미 만들어진 창에서 DPI 모드를 변경하지 않습니다. 이 확인은 좌표 체계의 전제 조건 확인이며 혼합 DPI 실기 검증을 대체하지 않습니다.

- `Geometry(x, y, width, height)`와 `Monitor(left, top, width, height)`는 엄격한 정수 범위를 검사합니다.
- `monitor_list(mss.monitors[1:])`: 전체 가상 화면인 MSS 인덱스 0을 제외합니다.
- `window_geometry(window)` / `apply_geometry(window, geometry)`: Windows에서는 `GetWindowRect` / `SetWindowPos`의 절대 좌표를 사용합니다. Tk의 음수 위치 표기(반대쪽 가장자리로부터 거리)를 Windows 절대 좌표로 오해하지 않습니다.
- `fit_geometry(geometry, monitors)`, `load_placement()`, `save_placement(geometry)`, `restore_placement(window, monitors)`를 독립적으로 사용할 수 있습니다.
- `OverlayPlacementEditor(root, window, monitors, pause=..., set_interactive=..., finished=..., on_change=...)`는 임시 편집 UI입니다. `set_interactive(True)`는 창을 입력 가능하게 만들고 성공 여부를 bool로 반환해야 합니다. `finished(saved, geometry)`는 원하는 모드를 복구합니다. `on_change()`는 별도 배경 창 동기화에 사용합니다.

부모는 처리 중인 OCR/번역 작업이 있으면 편집을 거부하고 먼저 중지시켜야 합니다. `pause` 콜백은 UI 추가 전에 실행됩니다. 편집 중 캡처를 재개하지 않도록 부모가 제어하고, 닫을 때도 자동 재시작하지 않습니다. 부모는 모드 변경 실패와 저장/복구 오류를 사용자에게 알리고 안전하게 중지해야 합니다. 배경 창도 본체 위치를 같은 물리 좌표 방식으로 따라가야 합니다. 본체는 `overrideredirect(True)`로 테두리 없이 유지합니다.

## 검증 범위

Linux에서 순수 좌표·범위·저장 및 모의 DPI 검사를 자동 테스트합니다. 이 테스트는 실제 창 이동을 검증하지 않습니다. Windows 실기에서는 100/125/150/200% DPI, 서로 다른 DPI의 다중 모니터, 음수 좌표 모니터, 모니터 분리, 창 재실행, 저장 실패, 플레이 클릭 통과, 학습 텍스트 선택, 편집 막대 표시/제거, 캡처 일시 중지를 확인해야 합니다. 실제 Windows 게임, 혼합 DPI 창 이동 및 설치 실행은 이 작업에서 검증하지 않았습니다.
