# 실험적 Textractor CLI 연결

현재는 MIT 앱이 별도 설치된 GPL TextractorCLI를 표준 입출력으로 실행하는 **실험적** 연동이다. GPL 소스·DLL·실행 파일을 앱에 복사/링크/동봉하지 않는다. 자동 다운로드·재배포는 제공하지 않는다. 단순 프로세스 분리만으로 모든 라이선스 해석을 확정하지 않으며 통합 배포 전 별도 검토가 필요하다.

## 구현

- 직접 고른 가시 창 프로세스의 PID·생성 시각·실행 파일·x86/x64를 읽기 전용으로 확인한다. 관리자 권한을 요청하지 않는다.
- 별도 공식 5.2.0 CLI 폴더를 사용자가 선택하고 위험 고지 체크 및 연결 직전 확인을 모두 해야 `attach -P숫자`를 보낸다. 실행 직전 대상 식별자를 다시 확인하지만 극히 짧은 종료 경합을 완벽히 제거한다고 보장하지 않는다.
- 엔진이 자동 인식한 후크의 실제 후보를 UTF-16LE 표준 출력에서 수신한다. 후보 32개/문장 2,000자/세션 1,000이벤트/대기열 64개/출력 줄 8,192자 제한. 선택 대상 PID가 아닌 출력·콘솔·메타데이터 없는 줄은 버린다. 여러 줄 문장은 이어붙이지 않아 일부가 누락될 수 있다. 게임 원문을 명령으로 실행하지 않는다.
- 후보는 로컬에서 갱신·참고 순위 표시하며 자동 선택하지 않는다. 선택 후 명시적 1회 전송 확인을 거쳐 기존 DeepL/로컬 번역의 키·동의·비용 한도·늦은 응답 폐기를 사용한다. 후보 변경/종료 시 이전 번역 결과를 폐기한다. API 오류에 자동 재시도/유료 전환 없음.
- 30초간 후보가 없거나 게임 식별자가 바뀌거나 CLI/파싱/입력 한도가 실패하면 중지한다. 해제는 `detach` 요청 후 소유 CLI만 종료한다. **CLI에 해제 ACK가 없으므로 게임에서 후크가 제거됐다고 확인할 수 없다.** 게임 종료를 강제하지 않으며 필요 시 저장 후 사용자가 직접 종료한다. 창을 닫아 OCR 설정으로 돌아가도 자동 캡처를 시작하지 않는다.

광범위 `FindHooks` 메모리 탐색, 수동 후킹코드 삽입, 프로필 저장·재연결은 아직 미구현이다. 선택 후보 연속 번역은 아래 후속 개발 절에 설명한다. 자동 후보 수신은 엔진의 기존 자동 감지 결과이며 모든 게임/모든 후크를 탐색한다는 뜻이 아니다. 별도 도구 설치가 필요하므로 비개발자용 한 번 설치 목표는 아직 달성하지 못했다.

## 중요한 경계

upstream host의 고정 이름 named pipe와 permissive ACL, 클립보드 로컬 읽기, 연결/해제 ACK 부재를 확인했다. 앱의 표준 입출력 통신이 이 upstream 내부 위험을 없애지 않는다. 동일 컴퓨터의 다른 프로세스에 대한 출처 인증을 보장하지 않으며 출력 PID는 암호학적 증명이 아니다. 이를 개선한 호스트 없이는 기본 번들/정식 권장 엔진으로 승격하지 않는다. 콘솔/클립보드 후보(PID 0)는 Kotoba에서 버리고 외부 전송하지 않는다. CLI 환경에 API 키·일반 환경변수는 상속하지 않는다. 게임 경로는 프로세스 선택 창의 로컬 표시만 사용하며 저장/전송하지 않는다.

후킹은 게임 프로세스를 변경하고 충돌/진행 손실을 일으킬 수 있다. 온라인/안티치트 게임에 사용하지 않는다. 보호·인증·보안 경고·권한 실패 시 중단하고 정상 인증을 유지한다. 특정 게임의 인증 안내만으로 설치 판의 보호 방식을 추정하거나 패치를 권하지 않는다. 관리자 승격, 안티치트 우회, 보안 설정 변경은 하지 않는다.

## 검증 구분

Linux 단위 테스트는 UTF-16 CLI 문장 형식의 합성 문자열, PID 필터/재사용, 명령 제한, 잘못된 바이너리, 동의 없음, 입력 폭주, 종료/버퍼 폐기를 검증한다. 실제 Windows API와 실행 파일 시험을 대체하지 않는다.

`Experimental hook CLI fixture` CI는 공식 ZIP 해시를 확인하고 먼저 빈 stdin으로 CLI를 종료한다. 그 다음 이번 테스트가 직접 생성한 보호 없는 GDI 창에만 연결해 고정 합성 문장이 수신되는지 확인한다. 사용자 프로세스를 탐색해서 연결하지 않으며 실제 게임·키·번역 API는 사용하지 않는다. 테스트 결과는 해당 커밋의 Actions가 기준이다. 첫 Windows CI에서 CLI 무연결 실행과 fixture 빌드는 통과했으나 후보 수신이 실패했다. fixture 출력 간격이 엔진의 문장 flush 간격보다 짧았던 가능성을 검토해 간격을 1.2초로 바꾸고 재시험한다. 원인 확정/후킹 성공을 주장하지 않으며 실제 게임 후킹/해제 정상 동작은 미검증이다.


후속 실측: 커밋 `af49fad284c18578e32216f570ea54a25b841beb`의 [Windows Server 2025 x64 합성 CI](https://github.com/FioreFlower/Kotoba-Bridge/actions/runs/43494424498)는 공식 ZIP 검사, CLI 무연결 실행, 보호 없는 자체 GDI 프로그램 연결 후 일본어 후보 수신을 모두 통과했다. 1.2초 출력 간격에서 성공했으며 이전 실패의 모든 원인을 확정하는 것은 아니다. 실제 게임/32비트 연결/후크 제거 확인/저사양 성능은 여전히 미검증이다.

## 선택 후보 연속 번역 (후속 개발)

후보를 직접 선택하고 `선택 후보 연속 번역 켜기`에서 제공자·비용·계속 전송에 별도로 동의한다. 15초 안에 선택한 게임을 전경으로 가져오면 시작한다. 후보 안정화 0.6초와 최소 요청 간격 3초를 적용하고 동일 대사를 연속 재전송하지 않는다. 요청이 진행 중일 때 새 대사가 여러 번 오면 최신 대사 하나만 대기하므로 중간 대사는 생략될 수 있다. 번역 문맥/캐시는 같은 연속 선택 동안 기존 코어의 제한 안에서 유지한다.

게임 포커스 이탈, 모드/동의/후보 변경, 오류, 앱 정지/Esc는 연속 전송을 중지하며 자동 재개하지 않는다. 오래된 대사의 API 오류도 연속 모드를 중지한다. 사용량/요청 제한 오류를 자동 재시도하지 않는다. 전송 직전 게임 실행 인스턴스·전경 PID, 표시 직전 현재 후보/프로세스/전경을 다시 확인한다. 이미 전송된 요청의 비용은 취소되지 않으며 검사 사이의 매우 짧은 변경 경합을 완벽히 없앤다고 보장하지 않는다.

연속 번역만 정지하면 로컬 후보 미리보기는 계속되고, `입력 중지 / 연결 해제 요청` 또는 창 닫기는 입력도 중단한다. 게임/CLI 종료·입력 한도/파싱 실패는 입력을 정리한다. 앱 종료 시 Windows Job Object는 **앱이 생성한 CLI만** 종료하며 사용자 게임을 강제로 종료하지 않는다. Job은 게임에 이미 설치된 후크 제거를 보장하지 않는다. 초기 Job 편입 전에 앱이 강제 종료되는 작은 경합은 남는다.

OCR과 후킹은 동시에 자동 실행하지 않는다. 후킹 창을 열면 OCR이 정지하고, 후킹 창이 열린 동안 OCR 시작을 거절한다. OCR로 복귀하려면 후킹 창을 닫고 영역을 확인한 뒤 사용자가 시작해야 한다. 앱의 Esc는 전역 단축키가 아니다. 실제 게임 연결 전에는 테스트 준비 결과를 보고하고 해당 게임·실행에 대한 승인을 받아야 한다.

합성 상태/목업 테스트는 중복·최신 대사 우선·느린 응답·오래된 오류·포커스 이탈·선택 변경·정지와 늦은 응답 폐기를 검증한다. 연속 번역의 실제 게임 품질·지연은 아직 검증하지 않았다. 네이버 검색은 공개 합성 단어로 확인했으며 DeepL usage는 실제 키 없이 HTTP 목업으로만 검증했다. 새 도구의 사용자 PC 실행이나 실제 게임 연결은 수행하지 않았다.
