# 선택형 게임 텍스트 입력원 검토

검토일: 2026-11-13. 공식 저장소와 공식 문서를 읽은 설계 조사이며 Windows 게임 실행·후킹·성능 검증 결과가 아니다.

**현재 구현은 OCR·데모·사용자가 명시적으로 붙여넣은 원문의 1회 번역이다.** 합성 후보 선택 체험은 로컬 테스트 UI이며 실제 게임 탐색이 아니다. 파일·파이프·WebSocket·Textractor/LunaTranslator 직접 연동은 미구현이다. Kotoba Bridge는 게임 프로세스에 주입하지 않는다. OCR 개발과 설치 개선을 우선하고, 입력원 인터페이스를 추후 확장하는 방향이다.

## 가치와 선택

| 입력원 | 가치 | 제약·전송 위험 | 현재 상태 |
| --- | --- | --- | --- |
| 선택 영역 로컬 OCR | 게임 엔진에 독립적이고 게임 메모리를 변경하지 않음 | 장식 글꼴·루비·세로쓰기·배경·텍스트 애니메이션 오인식, 캡처 영역에 다른 창이 덮이면 사적 텍스트 인식 가능 | 구현됨. Windows 실기 품질 미검증 |

| 별도 설치된 텍스트 후킹 도구의 출력 | 지원되는 게임에서 OCR 오인식과 캡처 비용을 줄일 가능성 | 엔진·게임 패치·32/64비트·보호 기능에 따라 실패·충돌 가능. 화면에 아직 없는 대사나 중복 스트림도 들어올 수 있음 | 조사만 수행 |

후킹이 정확도나 저사양 성능을 항상 개선한다고 주장하지 않는다. 동일 장면에서 OCR 대비 문자 오류, 첫 대사 지연, CPU·메모리, 게임 프레임 변화와 종료 후 정상 복귀를 측정해야 한다. 원문이 잘 추출되어도 화자 분리·루비·문장 경계와 번역 품질은 별도 문제다.

## 공식 도구 확인

### Textractor

공식 README는 Windows 7 이상과 Wine의 x86/x64 게임 텍스트 도구로 소개하며 여러 엔진의 자동 후킹과 확장 기능을 설명한다. 호스트가 게임 프로세스에 `texthook`를 주입하고 파이프를 통해 텍스트를 받는 구조다. 이 내부 파이프를 Kotoba Bridge의 공개 연동 API로 간주하지 않는다. upstream의 OS 표기는 Kotoba Bridge의 Windows 7 지원 약속이 아니다. [공식 README](https://github.com/Artikash/Textractor/blob/master/README.md)

upstream에는 선택된 게임 텍스트를 Windows 클립보드로 복사하는 확장이 있다. 따라서 사용자가 도구를 별도로 설치·설정하고 원문을 복사한 뒤 Kotoba Bridge에 명시적으로 붙여넣는 흐름은 구현 후보가 된다. 이 조사에서는 확장 코드를 복사하거나 실행하지 않았다. 클립보드 복사는 기존 클립보드 내용을 바꾸며 클립보드 기록·동기화 설정의 영향도 받을 수 있다. [공식 확장 소스](https://github.com/Artikash/Textractor/blob/master/extensions/copyclipboard.cpp)

### LunaTranslator

공식 기본 사용법은 HOOK·OCR 입력과 게임 프로세스 선택 후 주입, 여러 후보 텍스트 중 선택하는 흐름을 설명한다. Kotoba Bridge에서 같은 게임 실행/주입 자동화를 구현하거나 위임하지 않는다. [공식 기본 사용법](https://docs.lunatranslator.org/en/basicuse.html)

공식 배포 문서는 일반 64비트판에 Windows 10 1803 이상/11을 표시한다. 이는 해당 도구의 표기이며 개별 게임, 현재 릴리스 또는 Kotoba Bridge 연동을 검증한 결과가 아니다. 문서의 보안 프로그램 예외·비활성화 안내는 본 프로젝트에서 채택하지 않는다. 보안 경고가 발생하면 작업을 중단하며 예외 추가, TLS 검증 해제, 관리자 권한 자동 요청을 하지 않는다. [공식 배포·FAQ](https://docs.lunatranslator.org/en/README.html)

후킹 입력도 한두 글자씩 도착하거나 계속 반복되고 대량 출력될 수 있다는 설명이 있다. OCR을 없애도 안정화·버퍼 제한은 필요하다. 후속 고정 커밋 조사에서 텍스트 출력 WebSocket은 확인했다. 그러나 프로세스/후보 열거를 제어하는 안정된 외부 API와 Kotoba Bridge 어댑터는 검증되지 않았다. 아래 인터페이스 조사 결과를 구분해서 읽어야 한다. [공식 HOOK 설정](https://docs.lunatranslator.org/en/hooksettings.html)

## MIT와 타사 라이선스 경계

두 공식 저장소의 LICENSE는 GNU GPL version 3 본문이다. 정확한 재배포 계획에서는 선택한 릴리스, 파일별 고지와 종속 구성요소를 다시 확인해야 한다. [Textractor LICENSE](https://github.com/Artikash/Textractor/blob/master/LICENSE), [LunaTranslator LICENSE](https://github.com/HIllya51/LunaTranslator/blob/main/LICENSE)

Kotoba Bridge의 자체 코드가 MIT인 것은 타사 GPL 코드까지 MIT로 바꿀 권한을 주지 않는다. 후킹 엔진·DLL·확장 소스를 가져와 MIT 코드에 합치지 않고, 현재 설치 파일에 두 도구를 번들하지 않는다. 사용자가 독립적으로 설치한 프로그램에서 나온 일반 텍스트를 받는 느슨한 연동을 우선 검토한다. 별도 프로세스 또는 파이프라는 사실만으로 모든 결합·배포 의무가 사라지는 것은 아니다. 공유 내부 구조나 전용 플러그인에 의존할 경우 결합 관계와 라이선스를 별도로 검토해야 한다.

향후 재배포·수정·번들링 시 GPL에 맞는 소스 제공, 저작권·라이선스 고지, 수정 고지 등 해당 의무를 확인하고, MIT 저장소의 범위와 타사 범위를 명확히 나눈다. 이는 기술·배포 설계 방향이며 법적 적합성 보증이 아니다. 게임 텍스트의 저작권과 게임 약관도 도구의 소프트웨어 라이선스와 별개다.

## 제안하는 입력 경계와 제어

다음은 **미구현 설계**다. 기존 OCR 경로를 바로 교체하지 않는다.

1. 단일 활성 입력원에서 `version, source, session_id, sequence, captured_at, text` 이벤트를 받아 공통 정규화·안정화·중복 제거·번역 정책으로 전달한다. 임의 명령, 실행 파일 경로, HTML 또는 원격 URL을 이벤트로 실행하지 않는다. 최대 크기·큐 길이·시간 제한을 두고 과부하 시 오래된 후보를 버린다.
2. 입력원 전환 시 이전 입력 수신과 번역 작업을 취소하고 세션 세대를 바꾼다. 이전 원문·문맥·대기열·화면 표시를 비우며 이전 세대의 늦은 응답을 폐기한다. 학습용으로 사용자가 저장한 항목은 별도 삭제 동작으로 남긴다.
3. OCR은 선택 게임 창의 활성 상태·위치·크기와 영역을 확인하며, 가림·포커스 변경 시 중단하는 방향을 시험한다. 단순 사각형 영역만으로 화면 출처를 보장할 수 없다. 외부 입력도 선택한 대상 게임과 입력 세션이 맞지 않거나 포커스를 잃으면 자동 번역을 중단한다. 수동 붙여넣기는 편집창에 있을 때만 받고 미리보기 후 번역 버튼으로 보낸다. 전역 클립보드 감시는 기본값으로 제공하지 않는다.
4. 파일은 사용자가 고른 단일 파일만 읽고 전체 폴더를 감시하지 않는다. 최초 전체 파일 자동 전송을 금지하고 바이트/문자 제한, 인코딩 오류, 회전·잘림·부분 쓰기를 처리한다. 파이프는 Windows 현재 사용자 전용 ACL, 로컬 연결, 버전 협상, 세션 토큰, 크기 제한을 전제로 한다. 무인증 localhost HTTP나 네트워크 수신 포트를 열지 않는다. 파이프 이름이나 PID만으로 신뢰를 판정하지 않는다.
5. 외부 도구 사용은 별도 선택과 설명 확인 후에만 활성화한다. 대상 게임과 선택 원문을 먼저 로컬 미리보기로 확인한다. 현재 MVP는 도구 설치·실행·관리자 승격·게임 자동 실행·프로세스 주입·자동 재연결을 수행하지 않는다. 향후 명시적 동의 후 별도 도구를 통해 연결하는 UX는 아래 제안 범위이며 아직 구현되지 않았다. 무인 주입이나 동의를 재사용한 자동 주입은 허용하지 않는다. 안티치트·DRM·보안 기능을 우회하지 않는다. 허용 여부가 불명확하거나 보호된 게임에서는 OCR로 돌아간다.
6. 항상 보이는 입력원 표시와 즉시 중지 동작을 둔다. 중지는 연결을 닫고 버퍼·문맥·대기 번역을 지운다. 이미 시작된 API 과금은 취소로 환불되지 않을 수 있다. Kotoba Bridge 중지가 외부 도구의 후크를 제거했다고 표시하지 않는다. 사용자가 외부 도구의 정상 종료 절차를 따르고 필요한 경우 게임을 정상 재시작하도록 안내한다. 강제 종료나 외부 게임 상태 변경은 수행하지 않는다.
7. 입력원별 로컬 미리보기 동의와 외부 번역 동의를 구분한다. API로 나가는 것은 선택 원문과 사용자가 허용한 문맥이며 화면 이미지·파일 경로·게임 PID·클립보드 전체를 보내지 않는다. 외부 도구 자체의 번역 API·로그·클립보드 동기화는 Kotoba Bridge가 통제할 수 없다고 고지한다. 두 도구의 번역이 동시에 켜져 이중 과금되지 않도록 설정을 확인하게 한다.
8. 모든 입력원에 동일한 요청 간격, 문자·요청 수 상한, 세션 예산, 중복 제거, 자동 재시도 금지를 적용한다. 스트림별 폭주 제한과 원문 미리보기를 거쳐야 한다. 안정화는 원문 내용을 추측해 완성하지 않는다. API 오류 시 원문을 유지하되 자동 반복 전송하지 않는다. API 키를 브리지 이벤트·진단 로그·게임/외부 도구에 전달하지 않는다.
9. 원문·번역 기록은 기존 로컬 기록/학습 정책과 분리되지 않게 관리한다. 입력 출처를 표기하고 기본 자동 영구 저장을 하지 않는다. 명시적 학습 저장과 기록 삭제를 제공하며 로그에는 대사·키를 기록하지 않는다. 앱 내부 삭제가 외부 도구 로그·클립보드 기록까지 삭제한다고 주장하지 않는다.

## 비개발자를 위한 후킹 연결 흐름 제안

이 절은 추가 사용자 요구를 반영한 **미구현 제품 설계**다. 일반 사용자가 후킹코드를 입력하거나 메모리 주소를 해석하지 않아도 되는 흐름을 목표로 한다. 현재 버전에서 게임 프로세스 선택이나 후보 탐색이 가능하다는 뜻은 아니다.

1. **게임 선택:** 사용자가 이미 실행한 게임의 창 제목·프로세스 이름·32/64비트를 보고 대상을 선택한다. 동일 이름의 프로세스가 여러 개면 명확히 구분하도록 하고 게임을 임의 실행하지 않는다. 실행 파일의 전체 경로는 로컬 확인용이며 외부 전송하지 않는다.
2. **주입 전 동의:** 선택한 게임과 외부 도구, 프로세스에 코드를 삽입하는 방식, 충돌·보안 경고·게임 약관상의 위험, OCR 대안을 표시한다. 사용자가 이번 연결에 명시적으로 동의하기 전에는 탐색이나 주입을 시작하지 않는다. 번역 API 전송 동의는 별도다. 관리자 권한·보안 예외·안티치트 우회가 필요한 경우 이 흐름에서 자동 해결하지 않고 중단한다.
3. **후보 자동 탐색:** 외부 도구가 제공하는 지원 엔진 탐지와 후보 스트림 열거 기능이 있을 때 이를 활용한다. 사용자에게 후킹코드를 요구하지 않는다. 지원하지 않는 게임에서는 코드 입력을 강요하지 않고 OCR로 안내한다. 고비용 탐색은 시간·후보 수·버퍼 상한과 취소 동작을 갖춰야 한다.
4. **대사를 진행하며 확인:** 사용자가 게임에서 몇 개 대사를 진행하는 동안 후보별 원문을 로컬에서 실시간 미리보기한다. 탐색 창은 사용자가 연 동안에만 표시하며 게임을 자동으로 가리거나 대사 진행을 멈추지 않는다. 번역 API에는 미선택 후보를 보내지 않는다.
5. **추천과 사용자 선택:** 갱신 시점, 일본어 비중, 길이, 반복률 등을 근거로 후보를 정렬하되 추천 사유를 보여 준다. 이름만 추출된 스트림, 메뉴·디버그 잡음, 같은 대사의 중복, 루비·문장 분할 때문에 점수가 높아도 정확한 대사임을 보장할 수 없다. 사용자가 화면의 실제 대사와 비교하여 하나를 선택한 뒤에만 자동 번역을 시작한다. 필요하면 후보를 다시 고르거나 OCR로 전환한다. 자동 추천을 검증된 정답이나 정확도 확률로 표시하지 않는다.
6. **게임별 선택 설정:** 저장에 동의한 경우 로컬 게임 식별자, 도구/프로토콜 버전, 선택 스트림의 재식별 정보와 안정화 설정만 저장한다. 대사 원문·번역·API 키는 이 프로필에 넣지 않는다. PID는 재실행 시 달라지므로 영구 식별자로 쓰지 않는다. 사용자가 프로필을 삭제할 수 있어야 한다. 게임 또는 도구 업데이트로 선택이 무효가 되면 재탐색하고 다시 확인한다. 저장 프로필을 불러오는 것과 새로운 주입 동의는 구분하며 무인 재주입하지 않는다.
7. **실패·중단·종료:** 후보 없음, 텍스트 변화 없음, 출력 폭주, 연결 오류 시 비용이 드는 재시도 없이 중지하고 OCR 복귀를 제시한다. OCR로 바꿀 때는 캡처 영역을 다시 확인한다. 사용자가 중지하거나 대상 게임 프로세스가 끝나면 해당 입력 세션, 로컬 연결, 대기열·문맥·미리보기를 정리하고 늦은 번역 응답을 버린다. 외부 도구의 후크 해제/정상 종료 API가 없다면 실제 해제를 완료했다고 표시하지 않고 사용자에게 별도 도구 종료 절차를 안내한다. 게임을 강제 종료하거나 다른 프로세스에 재연결하지 않는다.

### 구현 가능성과 외부 API의 한계

Textractor의 엔진 지원 및 확장 구조와 LunaTranslator의 후보 선택 UI는 이런 사용 흐름의 기술적 가능성을 뒷받침한다. 그러나 **동일한 UX를 Kotoba Bridge에서 제어할 수 있는 안정된 공개 API가 검증된 것은 아니다.** 클립보드로 최종 선택 텍스트를 받는 것만으로는 프로세스 목록·후보 열거·탐색 취소·후크 해제·버전 협상을 제어할 수 없다. Textractor의 내부 파이프도 공개 연동 계약으로 취급하지 않는다.

따라서 첫 단계에서는 외부 도구의 기존 선택 UI에서 사용자가 직접 연결·후보 선택을 수행하고 Kotoba Bridge는 승인된 원문만 받는 방식을 검토한다. 통합 마법사를 만들려면 upstream이 문서화한 API 또는 별도로 검토한 어댑터가 필요하다. 도구 UI의 좌표를 자동 클릭해 주입 동의를 대신하거나 비공개 내부 구조에 의존하는 구현은 배포 기반으로 삼지 않는다. GPL 도구용 전용 확장·어댑터 개발 및 재배포에는 라이선스 검토가 선행되어야 하며, 별도 실행 파일이라는 이유만으로 MIT 단일 라이선스로 포장하지 않는다. API가 없거나 권한·라이선스·게임 호환 조건을 충족하지 못하면 통합 흐름을 제공하지 않고 기존 OCR을 유지한다.

통합 구현 전에는 가짜 후보 스트림으로 추천 오류, 이름만 있는 후보, 중복·잡음, 후보 변경 중 늦은 응답, 게임 종료와 PID 재사용, 취소 후 재연결 금지, 설정 삭제를 시험해야 한다. 실제 게임별 주입·해제와 성능 검증은 별도 동의와 Windows 실기가 필요하며 이번 작업에서는 수행하지 않았다.

## 단계와 검증 조건

수동 붙여넣기 + 로컬 원문 확인·1회 번역과 합성 후보 체험을 구현했다. 후보 세션은 32개 스트림·각 2,000자·1,000개 이벤트로 제한하고 종료 시 지우며 이전 세대 입력을 폐기한다. 추천 순서는 정답을 의미하지 않고 자동 선택/전송하지 않는다. 합성 체험은 타이머나 실제 프로세스 탐색이 아니라 사용자가 다음 예제 대사를 누르는 검증용 흐름이다. 게임별 프로필 저장은 실제 출처 계약이 정해질 때까지 미구현이다. 파일/파이프는 가짜 입력 생산자로 폭주·중복·비정상 UTF-8·잘못된 버전·연결 종료·세션 전환·늦은 응답·비용 상한 테스트를 통과한 뒤 고려한다. 실제 후킹 도구와 연결하는 단계는 라이선스 검토 및 사용자가 허용한 오프라인 게임에서만 별도 검증한다.

검증 보고에는 게임/엔진/버전, 도구 릴리스, Windows 버전, 게임과 도구의 32/64비트, 입력원, 오류·성능 측정치를 적는다. 게임 이미지·사적 대사·API 키는 공개 테스트 자료에 넣지 않는다. 이번 문서 작성 중 게임 실행, DLL 주입, 도구 설치, 유료 API 호출은 하지 않았다. 외부 입력원이나 후킹 지원 완료를 의미하지 않는다.

공식 GitHub API로 조회한 기본 브랜치 커밋을 고정하여 다음 파일들을 읽었다. 도구 실행, DLL 로딩, 주입, WebSocket 접속, 유료 API 호출은 하지 않았다. 공개 소스의 함수가 존재하는 것과 외부 애플리케이션용으로 안정성을 보장한 API인 것은 다르다.

- Textractor: [`df5b830d1757a66aa162f8081e99d42c9bd50488`](https://github.com/Artikash/Textractor/commit/df5b830d1757a66aa162f8081e99d42c9bd50488)

### Textractor: 내부 호스트와 확장 경계

[`host/host.h`](https://github.com/Artikash/Textractor/blob/df5b830d1757a66aa162f8081e99d42c9bd50488/host/host.h)에는 `Host::Start`의 프로세스 연결/종료 및 텍스트 스레드 생성/제거/출력 콜백, `Host::FindHooks`, `Host::GetThread`, `Host::DetachProcess`가 선언되어 있다. 따라서 프로그램 내부에서 후보 이벤트를 받고 탐색·종료를 제어하는 기능은 존재한다. [`GUI/mainwindow.cpp`](https://github.com/Artikash/Textractor/blob/df5b830d1757a66aa162f8081e99d42c9bd50488/GUI/mainwindow.cpp)는 `GetAllProcesses()`로 프로세스를 얻고 `Host::Start(ProcessConnected, ProcessDisconnected, ThreadAdded, ThreadRemoved, SentenceReceived)`를 연결한다. 이들은 C++/Qt 호스트 내부 인터페이스이며, 설치된 별도 Textractor에 접속하여 프로세스/후보를 열거하는 버전 관리된 외부 서비스 API가 확인된 것은 아니다.

[`extensions/copyclipboard.cpp`](https://github.com/Artikash/Textractor/blob/df5b830d1757a66aa162f8081e99d42c9bd50488/extensions/copyclipboard.cpp)의 `ProcessSentence`는 `current select`와 `process id`를 검사한 뒤 문장만 `CF_UNICODETEXT`로 복사한다. 프로세스 ID, 후보/스레드 식별자, 이벤트 순서·시각·세션, 게임 종료 이벤트는 그 텍스트에 포함되지 않는다. 따라서 수신자가 클립보드 문자열만 보고 게임 출처나 현재 후보를 인증하거나 후보 목록을 복원할 수 없다. 현재 클립보드 소유자 정보도 게임 출처의 충분한 증명이 아니다. 같은 문장이 서로 다른 장면/게임에서 올 수 있고 다른 앱이 값을 덮어쓸 수 있다.

[`extensions/extension.h`](https://github.com/Artikash/Textractor/blob/df5b830d1757a66aa162f8081e99d42c9bd50488/extensions/extension.h)의 `SentenceInfo`는 확장 내부에 메타데이터를 전달하는 구조다. 이를 보존하는 새 확장은 수동 붙여넣기와 다른 개발·배포 작업이며, 해당 확장과 호스트의 GPL 결합 관계를 검토해야 한다. 이번 작업은 확장 소스를 복사하지 않았다.

### LunaTranslator: 공개 텍스트 출력은 존재, 후보 제어와 구분

[공식 Network Service 문서](https://docs.lunatranslator.org/en/apiservice.html)는 `/api/ws/text/origin` 원문 출력과 `/api/ws/text/trans` 번역 출력 WebSocket을 명시한다. 이전 조사에서 외부 출력 API를 확인하지 못했다고 적은 부분은 이 결과로 보완한다. API가 전혀 없다고 표현하면 부정확하다.

고정 커밋의 [`network/server/servicecollection.py`](https://github.com/HIllya51/LunaTranslator/blob/85c2234f34bab38def18e4f8f7c1e702e1344ade/src/LunaTranslator/network/server/servicecollection.py)에 `TextOutputOrigin`, `TextOutputTrans` 및 `registerall`이 있다. [`textio/textoutput/websocket.py`](https://github.com/HIllya51/LunaTranslator/blob/85c2234f34bab38def18e4f8f7c1e702e1344ade/src/LunaTranslator/textio/textoutput/websocket.py)의 `Outputer.dispatch(text, isorigin)`는 원문/번역에 해당하는 핸들러에 `send_text(text)`를 보낸다. 이 출력은 텍스트이며 후보 ID·게임 PID·선택/종료 상태를 담은 이벤트 계약이 아니다. [`textio/textoutput/clipboard.py`](https://github.com/HIllya51/LunaTranslator/blob/85c2234f34bab38def18e4f8f7c1e702e1344ade/src/LunaTranslator/textio/textoutput/clipboard.py)의 같은 메서드도 원문/번역 설정을 검사한 뒤 텍스트만 클립보드에 쓴다. 원문과 번역 출력을 함께 설정하면 번역문을 원문으로 오인할 위험도 별도로 다뤄야 한다.

검토한 공식 서비스 문서와 `registerall` 목록에서는 프로세스 목록, 후보 목록, 주입 동의, 후보 선택, 후크 해제를 제어하는 공개 엔드포인트를 찾지 못했다. 이는 조사한 범위의 결론이며 모든 향후 버전이나 별도 프로젝트에 그런 API가 없다는 증명은 아니다. 출력 WebSocket의 인증, 바인딩 주소, 외부 접근 차단, 버전 호환성도 실기 검증하지 않았다. 따라서 발견된 경로에 자동 접속하거나 네트워크 서비스를 자동 활성화하지 않는다.

[`textio/textsource/texthook.py`](https://github.com/HIllya51/LunaTranslator/blob/85c2234f34bab38def18e4f8f7c1e702e1344ade/src/LunaTranslator/textio/textsource/texthook.py)의 `initdll`은 `LunaHost32.dll` 또는 `LunaHost64.dll`을 로드하고 `Luna_Start`, `Luna_FindHooks`, `Luna_DetachProcess`, `Luna_QueryThreadHistory` 등을 ctypes로 바인딩한다. `ThreadParam`에는 `processId`, `addr`, `ctx`, `ctx2`가 있고 콜백은 `onnewhook`, `onremovehook`, `handle_output` 등으로 이어진다. 즉 후보/프로세스 정보를 갖는 내부 네이티브 경계는 실제로 존재하지만, 설치된 LunaTranslator를 밖에서 안전하게 제어하는 안정된 별도 프로세스 프로토콜로 검증된 것은 아니다. 이 DLL을 MIT 앱에서 직접 로드하는 방식은 단순 텍스트 수신과 다른 결합이며 별도 라이선스 및 배포 검토가 필요하다.

### 실제 구현에 적용할 결론

명시적 수동 클립보드 읽기 → 로컬 편집/확인 → 별도 번역 동의가 먼저 구현 가능한 범위다. 클립보드 읽기를 게임 프로세스 검증·후킹 연결 완료로 표시하면 안 된다. 합성 후보로 선택 UX를 시험할 경우 실제 게임 후보와 섞지 않고 시연임을 표시해야 한다. 이 문서 조사 자체는 수동 입력이나 합성 후보 UI의 구현 완료 증거가 아니며 실제 상태는 해당 코드·테스트·변경 이력으로 판단한다.

통합 후보 선택 마법사에는 메타데이터를 보존하는 별도 프로토콜과 upstream 협의 또는 검토된 어댑터가 필요하다. 현재 확인된 텍스트 전용 출력만으로 프로세스 선택·후보 추천·해제 확인까지 구현했다고 주장하지 않는다. GPL 코드를 MIT로 재표기하지 않는 원칙은 유지한다. 고정 커밋의 [Textractor LICENSE](https://github.com/Artikash/Textractor/blob/df5b830d1757a66aa162f8081e99d42c9bd50488/LICENSE)와 [LunaTranslator LICENSE](https://github.com/HIllya51/LunaTranslator/blob/85c2234f34bab38def18e4f8f7c1e702e1344ade/LICENSE)도 GPL version 3 본문임을 재확인했다. 별도 프로그램의 일반 텍스트를 수신하는 설계와 GPL 호스트/DLL/전용 확장을 가져오는 설계를 구분하며, 실제 배포 조합에 대한 법적 결론은 내리지 않는다.
